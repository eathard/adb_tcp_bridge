# ADB TCP 桥 —— Rust 重构实施计划

> 状态：**待批准，尚未实施**
> 本目录 `adb_bridge_rs/` 为全新工作区，与上级目录的 Python 实现完全隔离。
> **上级目录现有文件一律不改动**，`adb_tcp_bridge.py` 继续作为参考实现与对照基线。

---

## 1. 为什么做这次重构

| 目标 | Python 现状 | Rust 能带来的 |
|---|---|---|
| 单文件 exe | 需 Nuitka，且踩过 VS2022 路径、Scons SDK 缓存等坑 | `cargo build --release` 直接产出，约 10~20MB |
| 免安装部署 | 需 Python 环境 + PySide6 DLL，或 PyInstaller 40~70MB | 静态链接，无运行时依赖 |
| 原生 GUI | PySide6 可行但打包沉重 | egui 纯 Rust 原生，无 webview |
| 并发正确性 | 手工 `send_lock`/`self.lock`/`st.cond` 三处 | 编译期保证，`-race` 检测 |
| 内存安全 | 靠自觉 | 编译期保证 |

**性能不是理由。** 设备 C 走 USB，瓶颈是 USB 物理带宽，Rust 与 Python 拿不到用户可感知的差异。本次重构的目标是**可分发性与健壮性**。

| 字体 | 内嵌开源中文字体 | Rust 不依赖系统字体，避免方块字 |

### 关键简化：本项目无需 async

现有 `adb_tcp_bridge.py` 是**阻塞式 socket I/O**（`recv`/`sendall`/`read_exact` 全部同步）。
Rust 侧对应「一连接一 `std::thread` + `Mutex<VecDeque>` 队列」，与 Python 结构一一对应。

这样可以完全避开 Rust 最难的部分：所有权进阶、`Pin`、async 状态机。
重写是「照着翻译」，不是「重新设计」。

### 依赖清单（尽量少）

- `eframe` / `egui` —— GUI
- `r-efi` 不需要；`serde` + `serde_json` —— 状态输出
- `windows` crate —— 端口占用检测与进程清理（仅 Windows 分支）
- 无线上依赖；标准库 `std::net` 足够

### 阶段 1：协议核心（无 GUI，纯命令行）

目标：只做桥，不做界面，先用命令行证明协议实现正确。

模块划分：
```
src/
  proto.rs      ADB 包头、CNXN/OPEN/WRTE/OKAY/CLSE 打包解包
  server.rs     到本机 adb server 的 smart socket 客户端
  session.rs    单个客户端会话：握手 + stream 多路复用 + 流控
  stream.rs     单条 stream 的读写与背压
  bridge.rs     监听、accept、生命周期管理
  log.rs        日志分级 + 环形缓冲（供 GUI 读取）
  stats.rs      运行时统计（连接数、流量）
  config.rs     参数与持久化
  main.rs       命令行入口（先与 Python 版参数对齐）
```

必须原样搬运的正确性要点（**这些是踩过坑的地方，逐一对照**）：

1. **CNXN banner 必须带 `ro.product.*`**
   只给 `features` 会导致 adb 客户端不协商 `shell_v2`，退化为老 shell + PTY，
   后果是 stderr 与 stdout 合并、退出码丢失、TTY 检测产生 ANSI 颜色。
2. **banner 末尾不得附加 NUL**
   否则 features 变成 `"shell_v2\0"`，客户端匹配不到 `shell_v2` 而退回老协议。
3. **`on_open` 建连后必须把 socket 恢复为阻塞模式**
   ⚠️ **这是历史上最隐蔽的 bug**：Python 里
   `socket.create_connection(addr, timeout=10)` 会把超时**保留到 socket 上**，
   导致设备端 10 秒无输出时 `recv` 抛异常，被 `except: pass` 静默吞掉后断连。
   曾被误判为「adb server 的硬性超时」，加了心跳保活反而更糟（破坏流控与消息边界）。
   Rust 里对应 `TcpStream::set_read_timeout(None)`——**建连后立即调用**。
4. **OKAY 的 arg0/arg1 两个字段都要匹配**
   只匹配一个会在拥塞时误判，导致大文件 pull 卡死。
5. **上行必须队列化 + 独立写线程**
   主线程直接 `sendall` 会被大文件写入阻塞，无法转发设备响应。
   队列可合并多块后一次 `sendall` 提吞吐，但**每块仍须单独回一个 OKAY**
   （ADB 流控按包确认，少回会让对端卡住）。
6. **CNXN 的 maxdata 取 `min(对端值, MAXDATA)`**。
7. **watchdog 常驻**：每 10 秒确认 adb server 存活，断了拉起（部分环境会回收它）。
8. **不得使用心跳（`--heartbeat`）**：已证实有害，仅保留为实验开关，默认关闭。

验证方式（**不靠肉眼**）：
- `cargo test` 单元测试覆盖包头打包解包、流控窗口计算、OKAY 匹配
- 用真实设备跑冒烟：桥启动 → `adb connect` → shell/pull/push

### 阶段 2：一致性回归（关键闸门）

复用上级目录**现有测试脚本，一行不改**（它们走 adb 命令行，不依赖实现语言）：

| 测试 | 规模 | 作用 |
|---|---|---|
| `consistency_test.py` | 50 条 | USB 直连 vs 桥，逐条比对 stdout/stderr/退出码 |
| `consistency_test2.py` | 50 条 | 二进制/正则/Bash 高级/退出码/大流量流控 |
| `stress_test.py` | 12 项 | 基础压测 |
| `stress_advanced.py` | 11 项 | 大文件/半开连接/强杀 |
| `weaknet_*` | 5 档 | 弱网注入 |

**通过标准：100 条一致性 100/100，压测全绿，与 Python 版结果逐条一致。**
任何一条不一致都视为重构未完成，需定位后重跑。

注意跨机比较需先归一化换行（A 侧 CRLF / B 侧 LF，属 adb 客户端版本差异，与桥无关）。

### 阶段 3：GUI（egui）

在已验证的协议核心之上加界面，分五页（沿用已确认的原型）：

1. **控制台** —— 启停、核心指标、给 B 的连接命令（一键复制）、快速自检
2. **会话与流量** —— 接入客户端、每条 stream 的上/下行流量条、历史与断开原因
3. **运行日志** —— 分类过滤、暂停、清空、导出，读 `log.rs` 的环形缓冲
4. **参数设置** —— 端口、地址、serial、各开关，持久化到 `config.json`
5. **诊断工具** —— 一键自检 + 触发测试套件（**子进程执行**）

### GUI 性能纪律（三条硬性红线）

1. **转发线程内绝不触碰任何 GUI 对象**，日志一律投递队列。
2. **所有耗时操作 offload 到 worker 线程** —— 端口检查要跑
   `netstat`/`tasklist`，设备探测要跑 `adb`，放主线程会阻塞 UI 且占住 GIL 拖慢转发。
   （Rust 无 GIL，但仍会阻塞 UI 事件循环。）
3. **UI 刷新要稀**：连接数/流量 200~500ms 一次；日志用环形缓冲只留最近 N 行。

另加一个「性能对比自检」：同一组命令测开/关界面的吞吐与往返延迟，可自证无退化。

**测试套件必须 `spawn` 成独立子进程跑** —— 压测含强杀、半开连接、故意触发 EPIPE
等破坏性场景，在 GUI 同进程内跑可能把界面自身搞挂。
