# adb TCP 桥 部署指南

**适用版本**：1.0
**文档日期**：2026-10-07

本指南按顺序执行即可完成部署。全程约 10 分钟。

---

## 部署前准备

### 检查清单

| 项 | 要求 | 确认方式 |
|---|---|---|
| 电脑 A | Windows 或 Linux，能用 adb 连上设备 C | `adb devices` 能看到 C |
| 设备 C | 通过 USB 连在 A 上，已授权调试 | `adb shell id` 有输出 |
| 电脑 B | 与 A 同局域网，能 ping 通 A | `ping <A的IP>` |
| 端口 | A 上 15555 未被占用 | `netstat -ano \| findstr :15555` |

### 记录网络信息

在电脑 A 上执行，记下 A 的局域网 IP（B 要用它来连桥）：

```bash
ipconfig                          # Windows
ip -4 addr show scope global     # Linux
```

> 本文档示例使用：电脑 A = `172.16.0.106`，电脑 B = `172.16.0.101`。
> 请替换为你自己的实际地址。
>
> **不需要记设备 C 的 IP**。桥走的是 USB 上的 ADB 协议，不经过设备任何
> 网卡（RNDIS、以太网都无关）。设备侧只要 `adb devices` 能认到即可。

## 步骤一 · 确认设备已连接

在**电脑 A** 上执行：

```bash
adb devices -l
```

预期输出类似：

```
List of devices attached
b57290249a9b3206    device product:luckfox model:Luckfox
```

若显示 `unauthorized`，在设备上确认调试授权；若完全看不到设备，需检查驱动或更换 adb 版本（见软件说明书 7.4）。

验证 shell 可用：

```bash
adb -s b57290249a9b3206 shell id
# 预期：uid=0(root) gid=0(root)
```

---

## 步骤二 · 部署桥文件

将以下文件放到电脑 A 的同一个目录（例如 `D:\tools\adb-bridge\`）：

- `python/adb_tcp_bridge.py`（必需）
- `python/start_adb_bridge.bat`（Windows 便利脚本，可选）

Rust 版（`rust/target/release/adb_bridge_slint.exe` 等）是单文件 exe，
拷过去双击即可，无需 Python。

`tests/` 下的 `stress_*.py`、`weaknet_*.py` 等为测试工具，部署时可不复制。

确认 Python 可用：

```bash
python --version    # 需 3.7 或更高
```

桥**只使用 Python 标准库**，无需 pip 安装任何依赖。

## 步骤三 · 启动桥

### 方式 A：Windows 一键脚本（推荐）

双击 `start_adb_bridge.bat`。脚本已固定使用 15555 端口，并会在窗口内提示电脑 B 的连接命令。

### 方式 B：命令行启动

**Windows**

```bat
cd python
python adb_tcp_bridge.py --listen-port 15555
```

**Linux**

```bash
cd python
python3 adb_tcp_bridge.py --listen-port 15555 --listen-addr 0.0.0.0
```

### 预期输出

```
[20:19:26] 检查监听端口 15555 ...
[20:19:26] 端口 15555 可用
[20:19:26] 目标设备: b57290249a9b3206
[20:19:26] 设备 features: stat_v2,cmd,shell_v2
[20:19:26] 设备 product: luckfox
[20:19:26] 监听 0.0.0.0:15555 —— 电脑 B 执行: adb connect <本机IP>:15555
```

看到"监听"即表示启动成功。**保持该窗口开启**，关闭窗口即停止服务。

### 端口被占用时

桥启动时会先检查监听端口，若被上次残留的实例占用，会**自动结束占用进程**并继续启动：

```
[20:19:26] 检查监听端口 15558 ...
[cleanup] 端口 15558 已被占用: PID=14728 进程=adb_tcp_bridge.exe 监听=0.0.0.0
[cleanup] 结束进程 PID=14728 ...
[cleanup] 端口 15558 已释放（清理了 1 个进程）
[20:19:37] 端口 15558 清理完成，已结束 1 个残留进程
```

为避免误伤，**系统进程不会被自动结束**（`System`、`svchost.exe`、`explorer.exe`、`lsass.exe` 等）。若占用者是这类进程，需手动关闭后重试，或换一个端口。

不希望自动清理时（例如想先看清是谁在占用）：

```bash
python adb_tcp_bridge.py --listen-port 15555 --no-kill-port
```

此参数只报告不杀，占用未消除则退出并给出提示。也可单独检查某个端口：

```bash
python port_guard.py 15555        # 检查并清理 15555
```

### 多设备场景

若 A 上连接了多台设备，必须显式指定 serial：

```bash
python adb_tcp_bridge.py --listen-port 15555 --serial b57290249a9b3206
```

### 开机自启（可选）

Windows 可用任务计划程序，在"触发器 → 用户登录时"启动 `python adb_tcp_bridge.py --listen-port 15555`。

## 步骤四 · 放通防火墙

桥默认只监听本机可访问，局域网内其他机器需要 A 的防火墙放行。

### Windows（管理员 PowerShell）

```powershell
New-NetFirewallRule -Name "adb-bridge-15555" -DisplayName "adb TCP bridge 15555" `
  -Direction Inbound -Protocol TCP -LocalPort 15555 -Action Allow -Profile Any
```

### Linux（firewalld）

```bash
sudo firewall-cmd --permanent --add-port=15555/tcp
sudo firewall-cmd --reload
```

### 验证防火墙规则已生效

```powershell
Get-NetFirewallRule -Name "adb-bridge-15555" | Select-Object Enabled, Direction, Action
```

## 步骤五 · 在电脑 B 上连接

```bash
adb connect 172.16.0.106:15555
# 预期输出：connected to 172.16.0.106:15555

adb devices -l
# 预期多出一行：172.16.0.106:15555   device
```

### 验证连通性

```bash
adb -s 172.16.0.106:15555 shell id
# 预期：uid=0(root) gid=0(root)

adb -s 172.16.0.106:15555 shell uname -a
# 预期：Linux luckfox 6.1.99armv7l
```

> **提示**：后续命令都需带 `-s 172.16.0.106:15555`。若想省去，可在 B 上设置环境变量：
> ```bash
> export ADB_SERVER_SOCKET=tcp:172.16.0.106:15555   # 不推荐，见说明书
> ```
> 更简便的方式是写一个包装函数：
> ```bash
> d() { adb -s 172.16.0.106:15555 "$@"; }
> d shell id
> ```

## 步骤六 · 端到端验收

在电脑 B 上依次执行，确认全部成功：

```bash
S=172.16.0.106:15555

# 1) shell
adb -s $S shell id

# 2) 长命令（早期版本会在 10 秒处断开，此处可验证修复效果）
adb -s $S shell "sleep 20; echo LONG_CMD_OK"

# 3) 文件传输 + 完整性校验
head -c 1048576 /dev/urandom > /tmp/t.bin
M=$(md5sum /tmp/t.bin | cut -d' ' -f1)
adb -s $S push /tmp/t.bin /tmp/t.bin
D=$(adb -s $S shell md5sum /tmp/t.bin | cut -d' ' -f1)
[ "$M" = "$D" ] && echo "文件传输 OK" || echo "文件传输 失败"

# 4) 流控完整性（连续回读 12MB，比对 md5）
adb -s $S exec-out dd if=/dev/zero bs=1M count=12 | md5sum
# 期望：9a1347110f9fe8be206380caa480035b

# 4b) 换个尺寸交叉验证（1MB 与 4MB 的期望值）
adb -s $S exec-out dd if=/dev/zero bs=1M count=4 | md5sum
# 期望：b0072bec259e2d5b8fae0bfb039eb861
adb -s $S exec-out dd if=/dev/zero bs=1M count=1 | md5sum
# 期望：72a751c47ec746c22f6905c24b5b9ada

# 5) 清理
adb -s $S shell rm -f /tmp/t.bin
rm -f /tmp/t.bin
```

全部通过即部署完成。

### 建议做一次完整回归

如果需要在一台新环境验证部署效果，可运行完整测试（需先按步骤四临时放行 16666 端口）：

```bash
cd tests
python stress_test.py       # 基础 12 项，约 70 秒
python stress_advanced.py   # 进阶 11 项，约 150 秒（Windows 用 stress_advanced_win.py）
python consistency_test.py  # 第一批 50 条命令一致性比对
python consistency_test2.py # 第二批 50 条命令一致性比对
```

### 跨机一致性验证（可选）

第二批测试支持把 A 上「USB 直连」的结果导出为基线，再让 B 经桥跑同一批命令，
这样能在真实跨机路径上做对比（B 上没有 USB 线，无法自比）。

在 **A** 上执行，生成基线：

```bash
cd tests
python consistency_test2.py --export baseline_usb.json
```

把 `tests/consistency_test2.py` 与 `tests/baseline_usb.json` 传到 **B**，在 B 上执行：

```bash
adb connect 172.16.0.106:15555
python3 consistency_test2.py --baseline baseline_usb.json
```

预期输出 `跨机汇总: 50/50 完全一致, 0 条不一致`。

> 跨机模式会先归一化换行再比较：A 上是 Rockchip ADB 31，输出 CRLF；
> B 上是 ADB 34，输出 LF。这是两端 adb 客户端的版本差异，与桥的转发无关，
> 脚本会把这类差异单独统计为「仅换行符不同」，不计入不一致。

测试完成后可清理：`rm -f consistency_test2.py baseline_usb.json`。
（仓库里 `tests/baseline_usb.json` 是留档的基线，别误删。）

## 常见部署问题

### B 上 `adb connect` 报 `connection refused`

桥未成功启动，或监听在了 `127.0.0.1`。在 A 上确认：

```bash
netstat -ano | findstr :15555
```

预期看到 `0.0.0.0:15555 ... LISTENING`。若显示 `127.0.0.1:15555`，说明用了 `--listen-addr 127.0.0.1`，请改为 `0.0.0.0`。

### B 上 `adb connect` 报 `connection timed out`

防火墙未放行或网络不通。在 B 上：

```bash
# Windows
Test-NetConnection 172.16.0.106 -Port 15555

# Linux
nc -zv 172.16.0.106 15555
```

若端口可达但连接超时，检查 A 与 B 是否在不同网段（需路由转发），以及 A 的防火墙是否允许该网段入站。

### 连接成功但设备显示 `offline`

桥的握手应答异常。在 A 上用 `--debug-packets` 重启桥观察 CNXN 应答，参考软件说明书 4.4 节检查 banner 内容。

### A 上 `adb devices` 出现 `emulator-5554`

端口落在了 5555~5585，被 adb server 误认为模拟器。处理：

```bash
# 1. 用新端口启动桥
cd python
python adb_tcp_bridge.py --listen-port 15555

# 2. 清理旧防火墙规则（Windows 管理员）
netsh advfirewall firewall delete rule name="adb-bridge-5555"

# 3. 重启 adb server 清除幽灵设备
adb kill-server && adb start-server
```

### 官方 platform-tools 看不到设备

部分嵌入式板使用厂商定制的 USB 驱动（Windows 上依赖厂商的 `AdbWinApi.dll`），官方 adb 无法枚举设备，`adb devices` 为空。此时必须使用厂商提供的 adb，本软件对此无限制。

## 卸载

1. 关闭桥进程（在桥窗口按 Ctrl+C，或在任务管理器结束 `python` 进程）
2. 删除防火墙规则：

```powershell
Remove-NetFirewallRule -Name "adb-bridge-15555"
```

3. B 上断开连接：

```bash
adb disconnect 172.16.0.106:15555
```

4. 删除桥目录下的文件

设备 C 无需任何清理——桥对设备是完全只读的透明通道，未在设备上留下任何改动。

## 附录 A2 · 两种运行方式

桥有两种运行形态，功能完全一致，按场景选其一：

| | Python 版 | 二进制版 |
|---|---|---|
| 文件 | `python/adb_tcp_bridge.py` | `releases/python/adb_tcp_bridge.dist\adb_tcp_bridge.exe`（含依赖） |
| 环境要求 | 需 Python 3.7+ | **无需 Python**，目标机可直接运行 |
| 启动 | `python adb_tcp_bridge.py --listen-port 15555` | `adb_tcp_bridge.exe --listen-port 15555` |
| 适用 | 开发调试、改代码后即时生效 | 部署到其他电脑、长期运行 |

**两者都要求本机已安装 adb 且在 PATH 中**（桥通过 `adb` 子命令与设备通信）。

### 二进制版的编译

```bash
pip install nuitka scons pywin32 ordered-set zstandard
cd python
python build_nuitka.py
```

产物在 `releases/python/adb_tcp_bridge.dist\` 目录，整个目录一起拷贝即可运行。

> **若编译报 `scons environment variable 'CC' is not set`**
>
> 这不是编译器缺失，而是 Windows SDK 探测失败连带把 `CC` 置空。根因：Scons 通过
> `vcvars64.bat` 采集 MSVC 环境并缓存，该脚本内部调用 `reg.exe` 定位 SDK；若
> `reg.exe` 被安全策略拦截，缓存里会写入残缺值（`WindowsSDKVersion` 只剩一个
> 反斜杠、`WindowsSdkDir` 为空），Nuitka 解析失败即误判"未安装 SDK"。
>
> 运行 `python fix_nuitka_sdk_cache.py` 修补缓存后重新编译即可。该脚本只修改
> Nuitka 自己的缓存文件（会自动备份），不触碰注册表与系统配置。
>
> 前置条件：Visual Studio Build Tools 2022（含 C++ 生成工具）。可用以下命令确认：
> ```powershell
> "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
> ```

## 附录 B · 多台设备同时暴露

桥本身单进程只服务一台设备。多台设备需启动多个实例，用不同端口：

|设备 | 桥命令 | B 侧连接 |
|---|---|---|
| 设备一 | `--listen-port 15555 --serial <SERIAL_1>` | `adb connect <A>:15555` |
| 设备二 | `--listen-port 15556 --serial <SERIAL_2>` | `adb connect <A>:15556` |

防火墙需对每个端口各建一条规则。可将 `start_adb_bridge.bat` 复制多份并修改端口与 serial。
