# adb TCP 桥 部署指南

**适用版本**：1.0
**文档日期**：2026-10-07

本指南按顺序执行即可完成部署。全程约 10 分钟。

---

## 部署前准备

### 检查清单

| 项 | 要求 | 确认方式 |
|---|---|---|
| 电脑 A | Windows 或 Linux，能用 adb 连上设备 C | `adb devices` 能看到 C |
| 设备 C | 通过 USB 连在 A 上，已授权调试 | `adb shell id` 有输出 |
| 电脑 B | 与 A 同局域网，能 ping 通 A | `ping <A的IP>` |
| 端口 | A 上 15555 未被占用 | `netstat -ano \| findstr :15555` |

### 记录网络信息

在电脑 A 上执行，记下两处 IP：

```bash
# A 的局域网 IP（用于 B 连接桥）
ipconfig                          # Windows
ip -4 addr show scope global     # Linux

# A 上连接设备 C 的网卡 IP（设备通常以此为网关）
ipconfig | findstr 192.168.123   # 若设备是 RNDIS，一般为 192.168.123.x
```

> 本文档示例使用：电脑 A = `172.16.0.106`，电脑 B = `172.16.0.101`，设备 C = `192.168.123.100`。
> 请替换为你自己的实际地址。

## 步骤一 · 确认设备已连接

在**电脑 A** 上执行：

```bash
adb devices -l
```

预期输出类似：

```
List of devices attached
b57290249a9b3206    device product:luckfox model:Luckfox
```

若显示 `unauthorized`，在设备上确认调试授权；若完全看不到设备，需检查驱动或更换 adb 版本（见软件说明书 7.4）。

验证 shell 可用：

```bash
adb -s b57290249a9b3206 shell id
# 预期：uid=0(root) gid=0(root)
```

---

## 步骤二 · 部署桥文件

将以下文件放到电脑 A 的同一个目录（例如 `D:\tools\adb-bridge\`）：

- `adb_tcp_bridge.py`（必需）
- `start_adb_bridge.bat`（Windows 便利脚本，可选）

其余 `stress_*.py`、`weaknet_*.py` 等为测试工具，部署时可不复制。

确认 Python 可用：

```bash
python --version    # 需 3.7 或更高
```

桥**只使用 Python 标准库**，无需 pip 安装任何依赖。

---

## 步骤三 · 启动桥

### 方式 A：Windows 一键脚本（推荐）

双击 `start_adb_bridge.bat`。脚本已固定使用 15555 端口，并会在窗口内提示电脑 B 的连接命令。

### 方式 B：命令行启动

**Windows**

```bat
python adb_tcp_bridge.py --listen-port 15555
```

**Linux**

```bash
python3 adb_tcp_bridge.py --listen-port 15555 --listen-addr 0.0.0.0
```

### 预期输出

```
[02:22:10] 目标设备: b57290249a9b3206
[02:22:10] 设备 features: stat_v2,cmd,shell_v2
[02:22:10] 设备 product: luckfox
[02:22:10] 监听 0.0.0.0:15555 —— 电脑 B 执行: adb connect <本机IP>:15555
```

看到"监听"即表示启动成功。**保持该窗口开启**，关闭窗口即停止服务。

### 多设备场景

若 A 上连接了多台设备，必须显式指定 serial：

```bash
python adb_tcp_bridge.py --listen-port 15555 --serial b57290249a9b3206
```

### 开机自启（可选）

Windows 可用任务计划程序，在"触发器 → 用户登录时"启动 `python adb_tcp_bridge.py --listen-port 15555`。

## 步骤四 · 放通防火墙

桥默认只监听本机可访问，局域网内其他机器需要 A 的防火墙放行。

### Windows（管理员 PowerShell）

```powershell
New-NetFirewallRule -Name "adb-bridge-15555" -DisplayName "adb TCP bridge 15555" `
  -Direction Inbound -Protocol TCP -LocalPort 15555 -Action Allow -Profile Any
```

### Linux（firewalld）

```bash
sudo firewall-cmd --permanent --add-port=15555/tcp
sudo firewall-cmd --reload
```

### 验证防火墙规则已生效

```powershell
Get-NetFirewallRule -Name "adb-bridge-15555" | Select-Object Enabled, Direction, Action
```

---

## 步骤五 · 在电脑 B 上连接

```bash
adb connect 172.16.0.106:15555
# 预期输出：connected to 172.16.0.106:15555

adb devices -l
# 预期多出一行：172.16.0.106:15555   device
```

### 验证连通性

```bash
adb -s 172.16.0.106:15555 shell id
# 预期：uid=0(root) gid=0(root)

adb -s 172.16.0.106:15555 shell uname -a
# 预期：Linux luckfox 6.1.99armv7l
```

> **提示**：后续命令都需带 `-s 172.16.0.106:15555`。若想省去，可在 B 上设置环境变量：
> ```bash
> export ADB_SERVER_SOCKET=tcp:172.16.0.106:15555   # 不推荐，见说明书
> ```
> 更简便的方式是写一个包装函数：
> ```bash
> d() { adb -s 172.16.0.106:15555 "$@"; }
> d shell id
> ```

## 步骤六 · 端到端验收

在电脑 B 上依次执行，确认全部成功：

```bash
S=172.16.0.106:15555

# 1) shell
adb -s $S shell id

# 2) 长命令（早期版本会在 10 秒处断开，此处可验证修复效果）
adb -s $S shell "sleep 20; echo LONG_CMD_OK"

# 3) 文件传输 + 完整性校验
head -c 1048576 /dev/urandom > /tmp/t.bin
M=$(md5sum /tmp/t.bin | cut -d' ' -f1)
adb -s $S push /tmp/t.bin /tmp/t.bin
D=$(adb -s $S shell md5sum /tmp/t.bin | cut -d' ' -f1)
[ "$M" = "$D" ] && echo "文件传输 OK" || echo "文件传输 失败"

# 4) 流控完整性（连续回读 12MB，比对 md5）
adb -s $S exec-out dd if=/dev/zero bs=1M count=12 | md5sum
# 期望：9a1347110f9fe8be206380caa480035b

# 4b) 换个尺寸交叉验证（1MB 与 4MB 的期望值）
adb -s $S exec-out dd if=/dev/zero bs=1M count=4 | md5sum
# 期望：b0072bec259e2d5b8fae0bfb039eb861
adb -s $S exec-out dd if=/dev/zero bs=1M count=1 | md5sum
# 期望：72a751c47ec746c22f6905c24b5b9ada

# 5) 清理
adb -s $S shell rm -f /tmp/t.bin
rm -f /tmp/t.bin
```

全部通过即部署完成。

## 常见部署问题

### B 上 `adb connect` 报 `connection refused`

桥未成功启动，或监听在了 `127.0.0.1`。在 A 上确认：

```bash
netstat -ano | findstr :15555
```

预期看到 `0.0.0.0:15555 ... LISTENING`。若显示 `127.0.0.1:15555`，说明用了 `--listen-addr 127.0.0.1`，请改为 `0.0.0.0`。

### B 上 `adb connect` 报 `connection timed out`

防火墙未放行或网络不通。在 B 上：

```bash
# Windows
Test-NetConnection 172.16.0.106 -Port 15555

# Linux
nc -zv 172.16.0.106 15555
```

若端口可达但连接超时，检查 A 与 B 是否在不同网段（需路由转发），以及 A 的防火墙是否允许该网段入站。

### 连接成功但设备显示 `offline`

桥的握手应答异常。在 A 上用 `--debug-packets` 重启桥观察 CNXN 应答，参考软件说明书 4.3 节检查 banner 内容。

### A 上 `adb devices` 出现 `emulator-5554`

端口落在了 5555~5585，被 adb server 误认为模拟器。处理：

```bash
# 1. 用新端口启动桥
python adb_tcp_bridge.py --listen-port 15555

# 2. 清理旧防火墙规则（Windows 管理员）
netsh advfirewall firewall delete rule name="adb-bridge-5555"

# 3. 重启 adb server 清除幽灵设备
adb kill-server && adb start-server
```

### 官方 platform-tools 看不到设备

部分嵌入式板使用厂商定制的 USB 驱动（Windows 上依赖厂商的 `AdbWinApi.dll`），官方 adb 无法枚举设备，`adb devices` 为空。此时必须使用厂商提供的 adb，本软件对此无限制。

## 卸载

1. 关闭桥进程（在桥窗口按 Ctrl+C，或在任务管理器结束 `python` 进程）
2. 删除防火墙规则：

```powershell
Remove-NetFirewallRule -Name "adb-bridge-15555"
```

3. B 上断开连接：

```bash
adb disconnect 172.16.0.106:15555
```

4. 删除桥目录下的文件

设备 C 无需任何清理——桥对设备是完全只读的透明通道，未在设备上留下任何改动。

## 附录 A · 参数速查

```bash
# 默认部署（推荐）
python adb_tcp_bridge.py --listen-port 15555

# 指定设备
python adb_tcp_bridge.py --listen-port 15555 --serial b57290249a9b3206

# 多台设备：用不同端口分别暴露
python adb_tcp_bridge.py --listen-port 15555 --serial DEVICE_A
python adb_tcp_bridge.py --listen-port 15556 --serial DEVICE_B

# 仅本机可访问（调试用）
python adb_tcp_bridge.py --listen-port 15555 --listen-addr 127.0.0.1

# 排障：打印每个adb 包
python adb_tcp_bridge.py --listen-port 15555 --debug-packets
```

## 附录 B · 多台设备同时暴露

桥本身单进程只服务一台设备。多台设备需启动多个实例，用不同端口：

|设备 | 桥命令 | B 侧连接 |
|---|---|---|
| 设备一 | `--listen-port 15555 --serial <SERIAL_1>` | `adb connect <A>:15555` |
| 设备二 | `--listen-port 15556 --serial <SERIAL_2>` | `adb connect <A>:15556` |

防火墙需对每个端口各建一条规则。可将 `start_adb_bridge.bat` 复制多份并修改端口与 serial。
